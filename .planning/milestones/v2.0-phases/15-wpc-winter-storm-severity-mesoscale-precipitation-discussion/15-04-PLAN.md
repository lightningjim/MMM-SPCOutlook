<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote KML `<href>` → outbound fetch | Hrefs are harvested from a document downloaded over the network; whoever influences that document chooses the next fetch target. This is the primary SSRF surface on a home-network Raspberry Pi, where RFC1918 addresses are the interesting target. |
| remote KMZ bytes → `adm-zip` | An attacker-influenceable archive is opened and an entry is decompressed. |
| candidate count → outbound request volume | The index decides how many fetches this host makes per poll. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-13 | Spoofing / SSRF | `normalizeAdvisoryUrl` before every `fetchBinBuffer` | mitigate | Parse with `new URL`, then require `protocol` ∈ {`http:`,`https:`}, `hostname` exactly equal to the row's `allowedHost`, empty `username`/`password`, and empty `port`. Prefix matching is removed, so lookalike hosts, userinfo tricks and query decoys are all refused. Nine negative cases asserted in Task 1, including an RFC1918 target. |
| T-15-14 | Availability defect from an over-tight allowlist | `MD_HOST_PREFIX` scheme mismatch | mitigate | The live `http://` href is accepted and normalized to `https://` rather than refused; asserted as the first check in Task 1 and turned into probe scenario `spc-md-http-href-not-rejected-by-allowlist` in plan 15-08. An allowlist that refuses everything is a false "no active MDs", which for this product is the false-negative class the project exists to prevent. |
| T-15-15 | Tampering | post-allowlist redirect | mitigate | `fetchBinBuffer` already sends `redirect: "error"`, so an allowlisted URL cannot be redirected off-host after the check. The https normalization is what stops SPC's own 301 from tripping that guard, keeping the control enabled rather than forcing it to be relaxed. |
| T-15-16 | Denial of service | `adm-zip` on remote archives | mitigate | `extractSoleKmlEntry` refuses archives with more than 32 entries, entries whose declared uncompressed size exceeds 8 MB (live samples ~3 KB), and entry names containing `..` or an absolute prefix. Each refusal throws into the per-candidate catch. |
| T-15-17 | Denial of service | unbounded candidate list from a hostile index | mitigate | `ADVISORY_MAX_CANDIDATES` caps fetches at 60 per row per run, logs the truncation and sets `anyStale`, so amplification is bounded and the degrade is visible. Poll frequency stays bounded by WR-05's `updateInterval` clamp and CR-03's `_inFlight` guard. |
| T-15-18 | Information disclosure | a total advisory outage rendering as "none active" | mitigate | Index failure, unknown strategy, candidate truncation and per-candidate fetch failure all set `anyStale`, while a clean run with zero hits does not (D-04). |
</threat_model>
