## The single most important design detail in this plan

The MPD-04 scenario must be built so that **every candidate clears the Last-Modified pre-filter**.

The live case has `MPD_1281_final.kmz` carrying a January listing timestamp, which the 48h pre-filter
would reject on its own. If the fixture reproduces that timestamp, the scenario passes because of the
pre-filter — and mutating away the authoritative `ValidEndTi` gate would leave it GREEN. The scenario
would then certify MPD-04 while proving nothing about the mechanism that actually implements it.

So: give the stale high-numbered entry a **fresh** listing timestamp and a **stale** embedded
`IssueTime`/`ValidEndTi`. That is also the more hostile and more honest case, since research flagged
it is unknown whether WPC ever touches an old file's Last-Modified. Only the validity gate can then
reject it, and mutation 1 proves exactly that.
</critical_context>
