## Decisions Made

- Used `this.data && this.data.header` (rather than a bare `this.data.header`) to guard `this.data` itself against `undefined`/non-object per the plan's defensive-read instruction, matching the module's established "warn/guard, never throw out of a lifecycle method" posture — without this guard `getHeader.call({data: undefined})` would throw a `TypeError` instead of returning the fallback.
- Kept the fallback string as a bare literal with no interpolation, satisfying the T-19.1-01 threat mitigation and the acceptance criterion that `grep -c 'NWS Hazard Outlooks'` returns exactly 1.
- For the Scenario A mutation proof, changed `if (header === undefined)` to `if (!header)` rather than `if (header)` — the latter would be a nonsensical/inverted mutation (it would make every configured header fall back to the literal); `!header` is the actual regression the plan's comment describes (an absent-key check converted to a truthiness check, swallowing the `header: ""` opt-out).
