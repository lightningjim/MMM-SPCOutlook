<objective>
Wire the Hazards Outlook into the frontend's config surface and, critically, into the `getDom`
no-risk short-circuit — as **two independent `&&` terms**, one per independently renderable thing.

Purpose: this plan carries the phase's #2 risk, and it is not hypothetical. Phase 15 shipped a live
production defect of exactly this shape: the `getDom` no-risk gate had no advisory term, so a
location inside an active MPD rendered the literal "No Severe Weather Risk" and the MPD was never
displayed. This phase adds TWO independently renderable things — day rows and the window band — and
a location can be inside a `Hazardous Heat` window polygon with every `day3`..`day14` hazard array
empty. One OR'd predicate that only checks the day grid reproduces the Phase 15 bug exactly.

Output: two config defaults, two payload fields, two predicates, two gate terms. No rendering —
that is 16-05.
</objective>
