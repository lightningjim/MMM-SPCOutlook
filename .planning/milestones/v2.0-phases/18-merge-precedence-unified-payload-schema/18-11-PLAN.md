<objective>
Close the `sources[].reportedDays` over-reporting defect logged in `deferred-items.md`: a disabled
`wpc-ero` or `wpc-wssi` currently populates `reportedDays` with every day of its span even though
no fetch ever ran, because `_runArcGisDayProduct` seeds every `day{N}Risk` to the string `"NONE"`
before its own toggle gate and `_addRegistryDayGridEntries` reads a string either way.

Purpose: this defect is being closed here rather than carried forward because Phase 19 is a display
rewrite that consumes exactly this payload, with no legacy fallback — a renderer that reads the raw
`reportedDays` array is precisely the consumer `deferred-items.md` names as the one that would be
misled, and it does not exist yet only because Phase 19 has not been written. 18-05's mitigation
gates `sources[].reporting` on `enabled`, which covers every caller that reads `reporting`, but the
raw array is still wrong and is still emitted. The root cause lives in the same 18-04-authored
grid-entry builder family this gap-closure run is already touching, and the fix is one gate plus
two argument threads, so bundling it here is materially cheaper than a separate future pass.

Output: `_addRegistryDayGridEntries` skips `noteReported` when the product's toggle is off,
mirroring HeatRisk's empty-`gridTuples`-when-off pattern, plus a mutation-proven probe scenario.
</objective>
