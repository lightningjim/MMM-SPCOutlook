Add `_resolveGridDayPrecedence(day, dayNumber, reportedDays)`. It mutates one grid day's `hazards`
array in place: it sets `suppressedBy` on every entry and then orders the array. It performs no I/O
and reads no clock.

Resolution, per dimension present in that day's entries:
  - Look up `PRECEDENCE[dimension]`. A dimension with no `PRECEDENCE` entry cannot happen —
    `assertTaxonomyIntegrity` rejects it at load — but guard anyway and leave such entries with
    `suppressedBy: null`, contained per entry, never thrown (a single unresolvable entry degrades
    itself, never the day's list).
  - Walk the rank order. The winner is the FIRST source id in that order that has an entry on this
    day. Entries only exist for above-floor readings (plans 18-03/18-04 applied the floor at
    creation), so "has an entry" already means "is an active claim".
  - The winner's entries keep `suppressedBy: null`. Every other entry on that dimension gets
    `suppressedBy` set to the winner's source id.
  - Before setting anything, branch explicitly on whether the rank-1 source REPORTED for this day:
    `reportedDays[rank1Id]` exists and contains `dayNumber` — the accumulator is lazily keyed, so an
    absent key means the source produced no reading at all and must read as "did not report", not
    throw. Keep two structurally distinct branches, or one branch
    where rank-1-absent short-circuits before the reporting check is used, and comment each. This is
    RESEARCH.md's explicit requirement: "SPC forgot to report" (rank 1 absent from `reportedDays`)
    and "SPC reported below-floor" (present in `reportedDays`, absent from the entry list) must never
    be conflated by a future reader, even though both produce the same visible outcome — rank 2
    survives. Do not add a payload field for the distinction; it is already inspectable via
    `sources[].reportedDays` versus `sources[].activeDays`, which Task 3 emits.
  - `suppressedBy` is only ever a source id or `null`. Name it and log it as resolving competing
    claims: any log line this method emits must read as "dimension X resolved to source Y for grid
    day N", never as one source silencing another.

Entries whose `dimension` is `null` (D-07 unmapped) are excluded from resolution entirely: they never
suppress and are never suppressed, and always keep `suppressedBy: null`.

Ordering (D-15): sort the day's `hazards` array by `DIMENSION_ORDER` index, then — within one
dimension — surviving entries (`suppressedBy === null`) before suppressed ones, then by
`PRECEDENCE[dimension]` rank, then by `label.localeCompare`. Entries with `dimension: null` sort after
every dimensioned entry, alphabetically by label, matching the existing `labelRank` convention. The
sort must be total and deterministic: two polls over an unchanged forecast must produce byte-identical
arrays, for the same reason `compareLabels` exists. Emit every survivor, in order, with no cap and no
`primary` flag — row budget is a layout concern Phase 19 has not defined, and truncation is a layout
decision, not a precedence one.

Call `_resolveGridDayPrecedence` for each of the fourteen grid days from `getSpcOutlook`, after all
five entry-assembly calls and before the return statement.
