<objective>
Retire the legacy render path and settle the backend-emission deletion with a measured number
instead of an assumption.

**Sequencing, as required.** 18 D-01 kept the eight legacy payload blocks byte-for-byte expressly
so this phase would have a live old-versus-new reference to check the RPT-06 checklist against.
This plan runs only after plan 19-08 signs that checklist off — deleting the reference before the
checklist is verified would destroy the only tool capable of catching a silent parity break.

**A cost finding that changes the question, measured at planning time.** PROJECT.md's end state is
that the unified day report is the sole **render** path with no legacy fallback — which plan 19-06
already achieved and pinned with a static gate. Deleting the legacy *backend emission* is a
separate and much larger job than CONTEXT.md's "sequencing call" framing suggests: at planning time
`scripts/probe-payload-resilience.js` contained **156 `assertPayloadIntact` call sites** (that
function asserts `day1`..`day8`, `fireWeather` and their per-day keys directly) and **180
assertions reading `out.day1`..`day8` / `.fireWeather` / `.excessiveRain` / `.winterImpact` /
`.hazardsOutlook` / `.heatRisk`** across 124 scenarios. Deleting the emission therefore forces a
migration of substantially the whole 130+ scenario suite — the project's only executable
verification surface, every scenario of which is individually mutation-proven under 15 D-10.

That is a genuine context-cost constraint, not a difficulty judgment: the migration cannot fit
inside one executor's context alongside anything else, and doing it badly would trade 130 proven
scenarios for an unproven suite. The planner does not get to decide this quietly, so this plan
measures it, presents it, and lets the operator choose.

Purpose: RPT-01 (no per-product sections remain), RPT-06 (nothing lost in the transition).
Output: a sole-reader proof, a discharged folded todo, a measured retirement decision.
</objective>
