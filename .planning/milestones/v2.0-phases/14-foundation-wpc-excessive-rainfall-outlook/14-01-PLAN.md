<threat_model>
## Trust Boundaries

This is a single-user local MagicMirror display appliance. There is no authentication, session, access-control, or multi-tenant surface anywhere in this module, and none is invented below.

| Boundary | Description |
|----------|-------------|
| node_helper process -> mapservices.weather.noaa.gov | Outbound HTTPS GET to a first-party NOAA ArcGIS service; the response body is external data parsed as JSON/GeoJSON |
| Caller code -> `buildArcGisQuery` | Internal, but the only place where a string is assembled into a network request URL — the injection point this plan is responsible for closing |

Note: ERO's query carries **no user coordinates**. The whole layer is fetched and point-in-polygon is evaluated locally, so the user's `lat`/`lon` are never transmitted to NOAA by this code path.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Tampering | `buildArcGisQuery(baseUrl, layerId)` | mitigate | Fixed 3-parameter template literal with no options object and no third parameter, so no caller can inject or reorder query parameters (D-09). `layerId` rejected unless `Number.isInteger(layerId) && layerId >= 0`, which blocks a string payload like `0/query?f=json&x=` from being concatenated into the path. `baseUrl` rejected unless it starts with `https://mapservices.weather.noaa.gov/`, an explicit host allowlist. Both guards throw. |
| T-14-02 | Tampering | ERO response CRS interpretation | mitigate | `f=geojson` written as a literal inside the return template, never a variable — no code path can emit `f=json`, whose Web Mercator meter coordinates would be silently misread as WGS84 degrees by turf (DATA-01). Task 3 verifies on the wire that max coordinate magnitude <= 180. |
| T-14-05 | Spoofing | NOAA endpoint identity | mitigate (partial) | Base URL is an absolute `https://` literal constant in source with no user-controllable host component; Node's default CA chain validation applies. Certificate pinning is explicitly **not** adopted — accepted residual risk: a single-user display with no ops process would silently break on NOAA cert rotation, a worse outcome than the risk it removes. |
| T-14-SC | Tampering | npm / package-manager installs | accept (not applicable) | This phase installs zero new packages. RESEARCH.md's Package Legitimacy Audit section confirms no `npm install` step exists in Phase 14 and no legitimacy gate is required. If Phases 15-17 introduce a package, the full Package Legitimacy Gate runs then. |
</threat_model>
