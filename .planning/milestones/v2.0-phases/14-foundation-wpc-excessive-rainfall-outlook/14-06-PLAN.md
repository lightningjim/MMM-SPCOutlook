<objective>
Build a committed, dependency-free Node probe that proves — offline, in one command — whether `getSpcOutlook` still returns a complete payload when the WPC ERO path receives a hostile response.

Purpose: Phase 14's verification found exactly one blocking gap (CR-01), and the reason it survived both the live probes and the human UAT is that nothing in this repository can exercise a failure path. Every "probe" run so far lived in a session scratchpad, depended on the live NOAA host being reachable, and was never re-runnable by the verifier. This plan closes that hole first, so plan 14-07's fixes land against a RED gate that turns GREEN — rather than against a claim. The harness is also the reusable asset the phase goal calls for: Phases 15-17 add four more registry rows to the identical fetch/parse loop, and each of them inherits a one-scenario cost to prove its own failure containment.

Output: `scripts/probe-lib/module-stubs.js` and `scripts/probe-payload-resilience.js`. Running the probe against the current (unfixed) code MUST exit non-zero and name the failing scenarios.

Create `scripts/probe-payload-resilience.js`, a self-contained CommonJS script run as `node scripts/probe-payload-resilience.js`.

Structure it as: shared fixtures, a payload-contract assertion, six scenarios, a runner, and a summary line with an exit code.

**Fixtures.** Define these module-scope constants.
- `ARCGIS_ERROR_BODY` — an object with a single `error` property holding `code: 400`, `message: "Unable to complete operation"`, and `details: []`. This is the documented ArcGIS REST failure shape returned inside an HTTP 200, and it has no `features` key.
- `MALFORMED_FEATURE_BODY` — an object with `type: "FeatureCollection"` and a `features` array containing one object with `type: "Feature"`, `properties: null`, and `geometry: null`. Structurally a FeatureCollection, individually hostile.
- `ERO_SLGT_BODY` — a well-formed FeatureCollection with one Polygon feature whose `properties` has `dn: 2` and `valid_time: "2026-08-19T12:00:00Z"`, and whose `geometry` has `type: "Polygon"` and a plausible closed ring of `[lon, lat]` pairs.
- `SPC_SLGT_BODY` — a well-formed FeatureCollection with one Polygon feature whose `properties` has `LABEL: "SLGT"` and whose geometry mirrors the shape above. This exercises the shared `extractPolygons` on the SPC categorical path.
- `PROBE_LAT` and `PROBE_LON` — a fixed coordinate pair, for example 38.9 and -77.0. Every scenario must pass the identical pair so `getSpcOutlook`'s location-change cache invalidation never fires mid-suite.

Never hardcode an ERO URL string — keying off `buildUrl` is what makes the probe survive a future layer-id change and is what keeps the URL byte-stability contract (PERF-02, D-09) in the probe's own dependency chain.
