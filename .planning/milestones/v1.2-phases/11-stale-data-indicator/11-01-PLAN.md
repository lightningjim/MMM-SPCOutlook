<objective>
Fix the latent stale-window bug (STALE-01) so the backend honors the user's configured `updateInterval` instead of silently falling back to 60 minutes.

Purpose: `node_helper` instances do not own `this.config`, so the existing `this.config?.updateInterval ?? 60` is always `undefined`-then-60. Threading `updateInterval` through the `GET_SPC_DATA` socket payload and persisting it on `this._updateInterval` makes the stale window reflect actual user intent.

Output: Updated `node_helper.js` with corrected helper signature, payload destructure, instance-field persistence, defensive fallback, and all call sites updated.
</objective>

| T-11-01 | Tampering | `updateInterval` field in `GET_SPC_DATA` payload | accept | Same-process IPC; no untrusted source. | T-11-04 | Repudiation | Stale-flag accuracy | mitigate (this plan IS the mitigation) | The bug currently understates staleness when `updateInterval > 60` (data appears fresh past the user's actual interval). Fix corrects the freshness signal users rely on for risk decisions. |
