```js
/**
 * Compute proximity weight to higher-tier polygons via linear falloff (40 km cutoff).
 * @param items - array of { label, value, poly, line } — `line` is pre-derived by caller
 *                via turf.polygonToLine and memoized on _geoJsonCache entries (Plan 12-03)
 * @param loc - turf point representing the query location
 * @param currentValue - the user's current tier value (e.g. result of evaluatePolygons against same items)
 * @param comparator - object with { initial, comparator(best, value) } shape; used to identify "higher tier" items
 * @returns { value: number, nextTier: string } when a higher-tier polygon is within 40 km, else null
 *
 * value = currentValue + weight, where weight = max(0, 1 - d_km/40), strictly capped below 1.
 * When two or more higher-tier polygons are within 40 km, the polygon producing the max weight wins;
 * nextTier is that winning polygon's label.
 *
 * IMPORTANT: this helper does NOT call turf.polygonToLine. Each item must carry a pre-derived `line`.
 */
computeProximity(items, loc, currentValue, comparator) {
  // 1. Filter to "higher tier" items: comparator.comparator(currentValue, item.value) !== currentValue
  //    This is the comparator-driven "higher than current" check (per D-13). For max-comparator
  //    (categorical and CIG both use Math.max), this means item.value > currentValue.
  // 2. For each higher-tier item:
  //    a. Read item.line (pre-derived by caller). DO NOT call turf.polygonToLine.
  //    b. Compute d_km via turf.pointToLineDistance(loc, line, { units: "kilometers" }).
  //       If item.line is a FeatureCollection (MultiPolygon source), iterate .features and take
  //       the min distance across all features.
  //    c. weight = Math.max(0, 1 - d_km / 40)
  //    d. Strict cap below 1: gate on d_km > 0 (per D-07's "simplest implementation"). When d_km === 0
  //       (user on boundary), treat as already inside higher tier and skip — return weight = 0 for this item.
  //       Equivalent: only contribute when d_km > 0 AND weight > 0.
  // 3. Track the item with the maximum weight across all higher-tier items.
  // 4. If no higher-tier item produced a positive weight, return null (per D-14, PROX-06).
  // 5. Otherwise return { value: currentValue + winningWeight, nextTier: winningItem.label }.
}
```

Implementation notes:
- The `items[i].label` IS the nextTier string for both categorical (`"ENH"`, `"MDT"`, ...) and CIG (`"CIG1"`, `"CIG2"`, `"CIG3"`) because `extractPolygons` carries the original LABEL through. No additional lookup needed inside the helper.
- `item.line` shape: Feature<LineString> for Polygon-source items, FeatureCollection<LineString> for MultiPolygon-source items. Branch on `line.type === "FeatureCollection"` to iterate `.features`; otherwise pass `line` directly to `pointToLineDistance`.
- Helper is pure: no `this._geoJsonCache` reads or writes inside `computeProximity`. The cache-level memoization Plan 12-03 wires up satisfies "per-render turf cost stays at O(1)" — by the time `computeProximity` is called, `item.line` already exists.

Per D-07: strict cap is enforced naturally by `d_km > 0` gate — `weight = 1` only at `d = 0`, which is excluded. No `Math.min(weight, 1 - EPSILON)` needed.

Per D-08: "higher tier" is comparator-driven, not hardcoded `>`. Use the comparator to test: an item is higher-tier when `comparator.comparator(currentValue, item.value) !== currentValue`. For both `catComparator` and `cigComparator` (Math.max), this reduces to `item.value > currentValue`, but routing through the comparator keeps the helper uniform if a future comparator changes semantics.
