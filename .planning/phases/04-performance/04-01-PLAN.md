<objective>
Eliminate redundant polygon math in node_helper.js — both across update cycles (PERF-01) and within a single cycle (PERF-02).

Purpose: The Raspberry Pi re-runs all turf point-in-polygon math on every update cycle even when NOAA hasn't changed the underlying GeoJSON. This burns unnecessary CPU on constrained hardware. Two sources of waste exist: (1) inter-cycle: same GeoJSON re-evaluated every cycle; (2) intra-cycle: Days 4-8 each call extractPolygons twice on the same geojson object.

Output: node_helper.js with a per-URL in-memory cache (ETag-first, SHA256 hash fallback), stale data fallback on fetch failure, location-change invalidation, and single-pass Days 4-8 extraction. No frontend changes required.
</objective>

```javascript
  const intervalMs = (this.config?.updateInterval ?? 60) * 60 * 1000;
  return (Date.now() - timestamp) < intervalMs;
},
```

Add `fetchGeoJsonCached(url)` as a method on the NodeHelper object, placed immediately after the existing `fetchGeoJson` method. This method:
1. Checks `this._geoJsonCache.get(url)` for an existing entry
2. If entry exists and `entry.mode === 'etag'`, adds `If-None-Match: entry.etag` header to the fetch request
3. On network/fetch error: if entry exists and `_isWithinStaleWindow(entry.timestamp)` is true, returns `{ data: null, cachedResult: entry.result, stale: true }`; otherwise returns `{ data: null, cachedResult: null, stale: false }`
4. On HTTP 304 (check `res.status === 304` BEFORE calling `res.text()` — 304 has no body): returns `{ data: null, cachedResult: entry.result, stale: false }` — cache hit via ETag
5. On non-ok HTTP response (not 304): same stale fallback logic as network error
6. On HTTP 200: reads raw text via `await res.text()`, checks for ETag header via `res.headers.get('etag')`
   - If ETag present: mode = 'etag', newHash = null, skip hash computation
   - If no ETag: mode = 'hash', compute `newHash = crypto.createHash('sha256').update(rawText).digest('hex')`
   - If mode === 'hash' AND entry exists AND `entry.hash === newHash`: content unchanged — update nothing (keep old timestamp), return `{ data: null, cachedResult: entry.result, stale: false }` — cache hit via hash
   - Otherwise (new or changed content): parse JSON from rawText, return `{ data, rawText, newEtag: res.headers.get('etag'), newHash, mode }` — cache miss, caller will run turf and update cache

Do NOT store the raw JSON text in the cache entry. Only store the 64-byte SHA256 hash string or the ETag string.

Cache entry shape (stored after turf evaluation by the caller):
```javascript
{
  mode: 'etag' | 'hash',
  etag: String | null,
  hash: String | null,
  result: Any,            // last turf evaluation result for this URL
  timestamp: Number       // Date.now() when result was last computed
}
```

The existing `fetchGeoJson` method remains unchanged — it is still used by getMesoscaleDiscussion (KMZ binary fetches) and should not be touched.

Log a `Log.info` cache hit message on both ETag and hash hits so behavior is verifiable in MagicMirror logs:
- ETag hit: `Log.info('MMM-SPCOutlook: cache hit (ETag) for ' + url)`
- Hash hit: `Log.info('MMM-SPCOutlook: cache hit (hash) for ' + url)`
- Stale fallback: `Log.info('MMM-SPCOutlook: stale fallback for ' + url)`

```javascript
} else if (fetch1Cat.data === null && fetch1Cat.cachedResult === null) {

  const gj = fetch1Cat.data;
```

**Part D — Fix Days 4-8 for PERF-02 (single-pass extraction):**

Replace the current Days 4-8 pattern (which calls extractPolygons twice on the same geojson) with the single-pass pattern. For each day 4-8:

```javascript
// Day 4 example — apply same pattern for days 5-8
const fetch4 = await this.fetchGeoJsonCached(day4URL);
let day4ProbRisk, day4Sign;
if (fetch4.data === null && fetch4.cachedResult !== null) {
  // cache hit — cachedResult stores { probRisk, sign } for day 4-8 URLs
  day4ProbRisk = fetch4.cachedResult.probRisk;
  day4Sign = fetch4.cachedResult.sign;
} else if (fetch4.data === null && fetch4.cachedResult === null) {
  day4ProbRisk = 0;
  day4Sign = false;
} else {
  const gj = fetch4.data;
  // SINGLE PASS: extract both polygon sets from the same geojson before any evaluatePolygons call
  const day4RiskPoly = this.extractPolygons(gj, label => label === "" ? 0 : parseFloat(label), (label, val) => val > 0);
  const day4SignPoly  = this.extractPolygons(gj, label => label, (label, val) => label === "SIGN");
  day4ProbRisk = this.evaluatePolygons(day4RiskPoly, loc, percComparator);
  // evaluatePolygons (turf) for SIGN is still conditional — extractPolygons (pure JS) is not
  day4Sign = day4ProbRisk > 0 ? this.evaluatePolygons(day4SignPoly, loc, sigComparator) : false;
  // Store { probRisk, sign } as the cached result for this URL
  this._geoJsonCache.set(day4URL, {
    mode: fetch4.mode,
    etag: fetch4.newEtag ?? null,
    hash: fetch4.newHash ?? null,
    result: { probRisk: day4ProbRisk, sign: day4Sign },
    timestamp: Date.now()
  });
}
const day4Risk = this.percToRisk(day4ProbRisk, day4Sign);
```

Note: Days 4-8 cache `result` as `{ probRisk, sign }` (an object), while Days 1-3 URLs cache scalar values. The per-URL cache handles this naturally.
