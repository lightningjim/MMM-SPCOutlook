## Resolution of the probe-harness conflict (planner decision, binding for this phase)

15-PATTERNS.md "Open Gap" and 15-RESEARCH.md "Validation Architecture" conflict:
`module-stubs.js` was deliberately built dependency-free ("executor git worktrees never carry an
untracked `node_modules` directory", module-stubs.js:1-10), while the research recommends building
synthetic KMZ fixtures with the **real** `adm-zip` and driving the real
`fetchBinBuffer → extractSoleKmlEntry → kmlToGeoJson` chain through the WR-09 `_fetch` seam.

**Chosen: use the real libraries, resolved opportunistically, with loud skips.**

- The four packages are resolved from the repo root at harness install time. When they resolve, the
  real module is registered and the KMZ chain executes for real. When they do not, today's throwing
  stub is registered and the 15 shipped scenarios run exactly as they do now.
- Scenarios that need the real chain declare `requires: "kml-deps"`. When unavailable they are
  reported `SKIP`, counted separately, and **the run exits non-zero**. A skip is a missing proof,
  not a pass, and the phase gate is `exit 0`.

**Why the alternative was rejected, and what it would have cost.** The alternative — keep the
zero-dependency posture and stub one layer higher, feeding pre-decoded GeoJSON objects into
`kmlToGeoJson`/`extractKmlFromKmz` — is exactly the mistake WR-09 was raised for ("stubbing too high
a layer" left the phase's headline fixes executed by no scenario at all). Concretely it would give up
coverage of three live-verified defects, each of which fails *silently*:
1. `extractSoleKmlEntry`'s entry selection. MPD's KMZ member is a fixed `doc.kml`, not the
   URL-derived `MPD_1118_final.kml` that `kmzToKmlfilename` computes. A pre-decoded fixture never
   opens the archive, so the wrong-member bug is unreachable.
2. `@tmcw/togeojson` wrapping `description` as `{ "@type": "html", value }` rather than a string.
   Hand-written GeoJSON fixtures would be authored with whichever shape the fixture author assumed,
   so the fixture would encode the bug rather than catch it. This is a 100%-silent-miss defect:
   nothing throws, every MPD just takes D-06's "no hazard type" branch forever.
3. `fetchBinBuffer`'s real `arrayBuffer() → Buffer` path for binary bodies.

**Cost accepted:** the advisory scenario family requires `npm ci` before it can run. That is a
one-line remedy printed by the runner, and the three libraries are already declared `dependencies`
in `package.json`, not optional extras.

`@turf/turf`, `node_helper` and `logger` stay stubbed exactly as today. The turf stub is
load-bearing — scenarios flip `turfStub.pointInPolygon` to place the user inside a polygon, and
WR-08's ring assertions are deliberate. Do not touch it.
</decision_record>
