## Planner decisions this plan implements (both were Claude's Discretion in 15-CONTEXT.md)

**Payload shape: flat, not nested.** D-03's target shape writes `winterImpact: { day1..day3 }`,
which is shorthand for the day span, not a statement about per-day field layout. `winterImpact`
emits the same flat `day{N}Risk` / `day{N}Text` / `day{N}Color` / `day{N}ValidTime` keys as
`excessiveRain`, for days 1-3. Rationale: the frontend's `["day" + d + "Risk"]` idiom, the probe's
`ERO_SUFFIXES` contract assertion, and the shared runner extracted in Task 1 all assume this shape.
Giving the twin product a different layout is the divergence D-02 exists to prevent, and Phase 18's
RPT-07 reshapes every product together anyway.

**Extract the ERO loop rather than duplicate it.** 15-PATTERNS.md establishes the ERO day-loop is
already fully generic over its registry row — every reference goes through `ero.*`. The extraction is
mechanical and its output contract is byte-identical, which the 11 `ero-*` scenarios and the
`spc-wellformed-baseline` golden snapshots verify. Phase 14 D-08's scope limit ("do not refactor the
existing SPC/fire-weather code") is respected: those paths are not touched.
</decision_record>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| WPC MapServer → `extractPolygons` | Remote GeoJSON, attacker-influenceable via upstream compromise or a hostile network path. |
| payload values → `innerHTML` | `getDom` concatenates payload values into an HTML string. |
| user config → outbound poll | `showWinterImpact` adds three more fetches per poll cycle. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-09 | Spoofing | `winterImpact.buildUrl` → `fetchGeoJsonCached` | mitigate | URL built solely by `buildArcGisQuery`, which refuses any baseUrl not on `https://mapservices.weather.noaa.gov/`; no remote value contributes to the URL. Untouched from Phase 14. |
| T-15-10 | Tampering (XSS) | WSSI row interpolated into `innerHTML` | mitigate | Only `tierToText` and `tierToColor` values reach `innerHTML`, and both are closed lookup maps keyed by a tier string the registry itself produced. `row.toValue` maps unrecognised remote `impact` values to `0`, so a hostile `impact` string can never become a map key or reach the DOM. Contrast with plan 15-07, where genuinely remote advisory text requires `escapeHtml`. |
| T-15-11 | Denial of service | three added fetches per poll | mitigate | Inherits WR-05's `updateInterval` validation and clamp on both ends plus CR-03's `_inFlight` guard; `withTimeout`'s 15s abort bounds each request. No new timer or fetch loop is introduced. |
| T-15-12 | Information disclosure | degraded WSSI read shown as an all-clear | mitigate | The runner returns `anyStale` for any stale or failed day and `getSpcOutlook` ORs it into the global flag, so a failed WSSI fetch produces the ⚠ badge instead of a confident "no winter impact" (CR-01's lesson applied to the new product). |
