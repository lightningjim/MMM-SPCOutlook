# Phase 19.1: Day report render width, product-neutral copy, and config key validation - Context

**Gathered:** 2026-09-09
**Status:** Ready for planning

<domain>
## Phase Boundary

Three post-UAT defect fixes against the Phase 19 unified day report. This phase delivers no new
render capability, no new data source, no payload-shape change, and no backend poll-orchestration
work. Every item traces to a numbered finding in `19-UAT.md`.

**In scope:**

1. **Render width (UAT test 5, major).** The detail-mode day report widens its MagicMirror region
   and overlaps the centre column. Compact rows are displaced too. Root-caused in `19-UAT.md`'s
   Gaps section; see Claude's Discretion below for the full constraint set.
2. **Product-neutral user-facing copy (UAT test 11, minor).** The loading string and the section
   header name only SPC while the module renders SPC convective/fire, SPC MD, WPC ERO, WPC WSSI,
   WPC MPD, WPC/CPC Hazards Outlook and NWS HeatRisk.
3. **Unrecognised config key surfacing (UAT test 13, minor).** MagicMirror merges unknown keys into
   `this.config` silently. A deployed `dayReportDetails` (plural) against the module's
   `dayReportDetail` (singular, `MMM-SPCOutlook.js:39`) was never read, and the operator believed
   detail mode was on when it never was — it cost real debugging time and invalidated a prior
   width observation.

**Explicitly out of scope:** UAT test 12 (first paint blocked by serial feed timeouts). See
`<deferred>`.

</domain>

<decisions>
## Implementation Decisions

### Phase scope

- **D-01: UAT test 12 is OUT of this phase** (operator decision). First-paint resilience under
  degraded feeds — an overall poll deadline or progressive render — is deferred to the backlog. It
  is not in this phase's title, the UAT cleared it as not a Phase 19 regression (cause was upstream
  feed degradation: ~40 sources each timing out to a stale fallback at ~15s serially; after
  redeploy, cold start measured 9166 ms then 4388 ms backend interval), and it is backend work in
  `node_helper.js`. Folding it in would make 19.1 span both files again — the exact combination
  `STATE.md`'s Recent Trend flags as needing `--depth=deep` review.

### Product-neutral copy

- **D-02: the module ships `getHeader()`, as a fallback only.** It returns `this.data.header`
  verbatim when the operator configured one, and the module's own neutral default otherwise. It
  never overrides a configured header. `getHeader()` does not exist in the module today (verified:
  zero matches for `getHeader`/`data.header` in `MMM-SPCOutlook.js`), so this is genuinely new code,
  not an edit.
  - **Why this and not documentation alone:** `SPC FORECAST` is the operator's own `header:` line in
    `config.js` and appears nowhere in this repository — the module has no other lever on it. A
    fallback means every new user lands on accurate copy by default while existing operators keep
    full control.
  - **Why not an unconditional override:** it would silently discard a setting the operator
    deliberately set, with no way to customise short of patching module source.

- **D-03: the umbrella name is NWS.** Header fallback `NWS Hazard Outlooks`; the loading string is
  reworded to the same umbrella (`Loading NWS outlooks...` or equivalent). Both strings MUST use the
  same umbrella — they are the same claim in two places.
  - **Why NWS over NOAA:** SPC, WPC and CPC are all NCEP service centers under the National Weather
    Service, and HeatRisk is an NWS product. Nothing this module renders originates outside NWS.
    NOAA is one level too coarse — it also covers NHC, OPC, NOS and the satellite/fisheries lines,
    none of which this module touches.
  - **Why not agency-less:** on a mirror, the agency name is what tells a viewer this is official
    guidance rather than a third-party app's interpretation.

- **D-04: `header: ""` is an explicit opt-out.** The fallback fires only when `this.data.header` is
  `undefined` (the key is absent from config). An explicit empty string is treated as a deliberate
  "no header" and returns empty. MagicMirror already distinguishes `undefined` from `""` in
  `this.data`, so this needs no new machinery.
  - **Why this matters:** MagicMirror paints the header region only when a string exists. Without
    this carve-out, an operator running the module headerless would silently gain a header row and
    lose a line of vertical space, with no way back short of patching source.
  - **Rejected:** a `showHeader` config flag. It would add an eleventh config key to the very phase
    that is adding validation to warn about config-key mistakes, and it duplicates a control
    MagicMirror already provides.

- **D-05: the sweep covers user-facing strings plus the README, and stops there.**
  - **Changed:** the `getHeader()` fallback default, the loading string (`MMM-SPCOutlook.js:1069`),
    and the README's description of what the module aggregates.
  - **NOT changed, deliberately:** the `Log.*("SPC Outlook: ...")` prefixes (~40 call sites across
    both files), the `GET_SPC_DATA` / `SPC_DATA_RESULT` notification names, the `this.spcrisk`
    payload field, and the `MMM-SPCOutlook` directory/module name. Renaming any of those is a
    breaking change to every existing install's `config.js` for zero user-visible gain, and the
    log-prefix sweep would inflate the diff of a phase whose real work is a render-width fix while
    breaking grep-ability of existing log history.

- **D-06: the empty-state copy is ALREADY product-neutral — do not touch it.** `NO_HAZARD_TEXT =
  "No Hazards Forecast"` (`MMM-SPCOutlook.js:1007`) with its `(unconfirmed)` (`:1008`) and
  `(filtered by settings)` (`:1017`) variants were already neutralised during Phase 19. The
  `Extended Hazards:` heading (`:811`), the stale badge, the advisory band's `in effect.` line
  (`:1271`) and the `Error: {error}` passthrough are all neutral as well. UAT issue 11's wording
  overstates the gap — the *only* SPC-named user-facing strings left are the loading text and the
  operator-owned header. These strings are RPT-06 parity targets; changing them would be a
  regression, not a fix.
  - **Consequence for the planner:** `19-UI-SPEC.md`'s Copywriting Contract table is stale on two
    counts — it lists the empty states as `No Severe Weather Risk` (superseded in Phase 19) and
    locks `Loading SPC Outlook...` as "unchanged" (superseded by D-03). Amend the table to match
    shipped reality rather than treating it as authoritative.

### Claude's Discretion

The operator left these three to me. They are NOT open questions for the researcher or planner to
re-ask the user — the constraints below are binding, and the mechanism choice within them is mine
(or the planner's) to make.

**Width fix mechanism (the major defect).** Every item verified in source at HEAD:

- Root cause: `MMM-SPCOutlook.js:644` builds `paddedFieldContent = dimensionField +
  labelContent.padEnd(DETAIL_LABEL_FIELD_WIDTH)` inside `<span style="white-space:pre-wrap">`.
  `DIMENSION_FIELD_WIDTH` is derived from the longest `DIMENSION_LABELS` value plus one (`:385-387`);
  `DETAIL_LABEL_FIELD_WIDTH = 23` (`:391`). Every row therefore carries a minimum of
  `2 + DIMENSION_FIELD_WIDTH + 23` monospace characters that `pre-wrap` forbids collapsing, setting
  a hard min-content width. MagicMirror sizes the region to its content.
- `also:` rows use the same literal-space strategy (`:665-674`), with
  `alsoIndent = " ".repeat(2 + dimensionField.length + 2)`.
- **Compact rows are displaced too**, so the fix must NOT be scoped to the detail sub-row renderer
  alone — the shared field padding is implicated.
- `19-UI-SPEC.md` spec-locks 23 as an exact character count ("This is the exact number; do not round
  or approximate it") and asserts the monospace column contract "does not require a new CSS file or
  `getStyles()` entry". A CSS-column approach (inline-block `ch` widths, a grid, or a table) changes
  that contract and needs a UI-SPEC amendment of the same kind BL-03 made. Make the amendment
  explicitly; do not leave the spec contradicting the code.
- `wrapper.style.textAlign = "left"` (`:1059`) is a shipped 19-08 gap closure for right-hand
  MagicMirror regions. Do not remove or weaken it while changing the column mechanism.
- Locked Phase 19 decisions the fix must preserve: D-05 (dimension grouping), D-06 (compact line
  restated verbatim as the header, never a second header string), BL-02 (a co-winner row leaves the
  dimension field blank so it reads as a peer), iteration-4 WR-02 (both winner and `also:` indents
  derive from `dimensionField.length`, the group's own rendered width, never the nominal constant),
  and WR-04 (truncate-then-pad order; the 60-character bound counts the entry's own source text,
  never the dimension prefix, the padding, or the module-authored proximity badge).
- No CSS file exists in the repo — all styling is inline per-span. `getStyles()` (`:222`) returns
  only the `weather-icons` stylesheet.
- The monospace font-family is already applied per-span
  (`'DejaVu Sans Mono','Liberation Mono',monospace`); DejaVu Sans Mono ships by default on
  Raspberry Pi OS.
- Do not use font-size for hierarchy (UI-SPEC, project constraint: viewing distance is meters).

**Width regression guard mechanism.**

- `scripts/probe-lib/module-stubs.js` has no real DOM: `assertInertMarkup` (`:363`) is regex-based
  and the harness's stated rule is core `vm`/`fs` only. `renderDom` (`:376`) returns markup, not
  layout.
- The existing `rpt03-*` scenarios assert column *indices* and therefore pass green while the layout
  overflows — index assertions are not a guard for this defect, which is the whole reason 123 green
  scenarios and the phase verifier both missed it.
- Candidate mechanisms: a structural proxy (assert the emitted markup carries no literal space-run
  padding, i.e. pin the *absence* of the defective construct), a single real-DOM scenario (needs a
  new devDependency such as `linkedom` plus an explicit, documented exception to the harness rule),
  or a `MANUAL ONLY` row on the parity checklist.
- Whichever is chosen must be mutation-proven per Phase 15 D-10: break the exact line it covers,
  confirm RED with a diagnosable message, restore. A scenario green under its own mutation is a
  fixture defect, not a pass.

**Config-key validation design.**

- The allowlist must cover the module's own `defaults` keys PLUS MagicMirror's per-module keys
  (`module`, `position`, `header`, `classes`, `disabled`, `hiddenOnStartup`, `config`,
  `configDeepMerge`, and the `animateIn`/`animateOut` pair on newer MM releases) or every real
  config produces false warnings. Verify the host key list against the installed MagicMirror
  version rather than trusting this list.
- Loudness: warn and continue, not throw. `hazardTaxonomy.js` (`assertTaxonomyIntegrity`, called at
  load) and `productRegistry.js` (`daySpanOf`) both throw at load time on invalid data, but those
  guard *static module source* — a bug that exists before the process polls. A user config typo is a
  different class and must not brick the mirror.
- Recommended shape: one `Log.warn` at `start()` naming each unrecognised key alongside its nearest
  `defaults` match. The actual failure was `dayReportDetails` vs `dayReportDetail` — a nearest-match
  hint is precisely what would have saved the UAT session, and a bare "unknown key" warning would
  not have.

</decisions>

## Specific Ideas

**Operator's own words (from `19-UAT.md`):**

- Issue 11: *"Also this is old text, too, since this is now a colleciton of NOAA Outlooks"*
- Issue 13: *"I can't tell a difference between dayReportDetails enabled or disabled"*
- Issue 5: *"This still seems to have a huge left-expansion on it. Actually goes into the Center
  column on the display itself"* — and on re-observation, *"Yes [width still pushes into the center
  column]"*

**Evidence status of the width defect.** Reconfirmed 2026-09-09 on `a89e981` with
`dayReportDetail: true` genuinely in effect. The earlier observation was invalid on two counts: it
ran against deployed `ca2a3f3` (21 commits behind main) AND global detail mode was never active
because the config carried the misspelled `dayReportDetails`, so every expanded day came from
`autoExpand` alone. The `also:`-indent fix (`84895f6`) did not address width.

**What the width fix must NOT regress** (confirmed passing in the same screenshot):

- The em-dash source-attribution column is straight.
- Co-equal hazards render as peers: Flash Flood Marginal / Heat Extreme on Day 1 rendered as
  co-winners, not with one demoted to `also:`.
- The detail flag reaches the renderer: Days 2/3/5/6/7 expand under the global flag, Days 1/4 under
  `autoExpand` alone, and an auto-expanded day carries no distinguishing chrome (D-04 holds in both
  directions).

**Reproducible visible symptom:** an 8-character label such as `Moderate` emits 15 trailing spaces
before the source attribution — the visible gap on Day 3 (Fri) in the operator's screenshot.

**Target hardware.** Reachable as `ssh mm` — Raspberry Pi 4 Model B, aarch64, Node v24.13.1.
Deployed coordinate is the OKC production one (35.4432156, -97.595822). `dayReportDetail: true` is
deliberately left on by the operator, not leftover state. Config backup at
`~/MagicMirror/config/config.js.bak-19uat`. Verifying the width fix requires a real render on this
hardware in a real region — it is not observable in the probe harness.

**Five UAT tests recorded NOT OBSERVABLE** at the deployed coordinate (no active SPC MD or WPC MPD,
no window-band entry, no proximity-only day, nothing stale, live hazards present so no all-clear).
If the width fix touches the band or empty-state render paths, those tests stay unobservable without
a substitute coordinate — budget for that rather than assuming a clean re-run.

<code_context>
## Existing Code Insights

### Reusable Assets

- `truncateHazardLabel()` / `escapeHtml()` / `validHazardColor()` — the shared guards every
  payload-derived string must pass through before reaching `innerHTML`. Any new element the width
  fix introduces reuses these verbatim.
- `detailColoredSpan()` / `detailSourceAttribution()` (`MMM-SPCOutlook.js` ~`:395-400`) — the two
  span builders the detail rows already compose. A CSS-column approach most likely changes what
  wraps these, not the functions themselves.
- `this.data.header` — MagicMirror already supplies the operator's configured header here, and
  already distinguishes absent (`undefined`) from explicitly empty (`""`). D-04 needs no new
  machinery.
- `resolveUpdateInterval()` (`:~48-62`) — the module's existing precedent for validating a single
  config value, logging one warning with a `_loggedIntervalFallback` once-only guard, and degrading
  to a safe default. The config-key validator should match this shape and its once-only-log idiom.
- `renderDom()` + `assertInertMarkup()` in `scripts/probe-lib/module-stubs.js` — the harness entry
  point for any new frontend scenario.

### Established Patterns

- **All styling is inline, per-span.** No CSS file exists; `getStyles()` returns only
  `weather-icons`. Introducing a stylesheet is a new pattern for this module and a UI-SPEC
  amendment, not a free choice.
- **Derive, never hardcode.** `DIMENSION_FIELD_WIDTH` is computed from `DIMENSION_LABELS`' own
  longest value; `alsoIndent` and `alsoLabelFieldWidth` are derived from it; `SIGNIFICANCE_FLOOR`
  and `hazardTaxonomy.js`'s integrity check follow the same rule. A width fix that reintroduces a
  magic number contradicts four milestones of convention.
- **Fail loud at load for module-authored data, warn and degrade for user input.**
  `assertTaxonomyIntegrity()` and `daySpanOf()` throw at `require()` time; `resolveUpdateInterval()`
  warns and falls back. Config-key validation belongs in the second category.
- **Mutation-prove every probe scenario individually (Phase 15 D-10, blocking).** A scenario green
  under its own mutation is a fixture defect. This is the bar the width guard must clear, and the
  bar the existing index-asserting scenarios failed to clear for this defect.
- **Frontend/backend restatement over sharing.** `MMM-SPCOutlook.js` runs in the browser and cannot
  `require()` `productRegistry.js`; label lists are restated fail-safe. Relevant if the config-key
  allowlist tempts anyone to share a key list across the two files.

### Integration Points

- `getHeader()` is a new MagicMirror lifecycle method on this module — it does not exist yet and has
  no current call site in the repo. MagicMirror calls it to paint the header region.
- `getDom()` (`:227`) is the sole render path; `19-06` gated this with
  `rpt01-getdom-reads-no-legacy-payload-block`. All three in-scope fixes except the header land
  inside or just above it.
- `start()` is where config-key validation runs (once, at load), alongside the existing
  `resolveUpdateInterval()` call.
- The eight legacy payload blocks are still emitted by `node_helper.js` but are unreachable on
  screen (deferred by operator decision 2026-09-07). They are not this phase's concern and must not
  be touched.

## Deferred Ideas

- **First-paint resilience under degraded feeds (UAT test 12).** An overall poll deadline, or
  progressive render as sources resolve, so a degraded network cannot hold first paint for minutes.
  Out of 19.1 by operator decision (D-01) — backend work in `node_helper.js`, not a Phase 19
  regression, and cleared under a healthy network. Belongs in the roadmap backlog.
- **Log-prefix neutrality sweep.** ~40 `Log.*("SPC Outlook: ...")` call sites across
  `MMM-SPCOutlook.js` and `node_helper.js`. Semi-user-facing (the operator reads `mm-out.log` during
  UAT) but a mechanical two-file sweep that would inflate this phase's diff and break grep-ability
  of existing log history. Revisit as its own cleanup pass.
- **Module/directory rename, notification rename (`GET_SPC_DATA` / `SPC_DATA_RESULT`), `spcrisk`
  field rename.** Breaking changes to every existing install's `config.js` for zero user-visible
  gain. Not worth it at any point short of a deliberate v3 break.
- **A `showHeader` config flag.** Considered and rejected in favour of honouring `header: ""`
  (D-04) — it would add an eleventh config key to the phase that is adding config-key validation,
  and duplicates a control MagicMirror already provides.
