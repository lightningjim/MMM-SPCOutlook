## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `wr02`/`uat05-co-winner-...`'s literal plan-specified mutation was a no-op for the target scenario's own fixture**

- **Found during:** Task 3, mutation cycle 3 (`uat05-co-winner-and-also-rows-derive-their-grid-tracks-from-the-groups-own-width`).
- **Issue:** The plan's mutation instruction (`detailRowOpen(dimensionTrackFr)` → `detailRowOpen(DIMENSION_FIELD_WIDTH)` at the `also:` call site) is the same physical code change `wr02`'s own docstring already names. Applying it broke `wr02` (which uses an unmapped, 29-character dimension where `dimensionTrackFr` and `DIMENSION_FIELD_WIDTH` diverge: 29 vs 13) but left `uat05-co-winner-...` green, because that scenario's fixture uses a mapped `"winter"` dimension where both quantities coincidentally equal 13 — the mutation had zero effect on its rendered output.
- **Fix:** Applied an equivalent mutation (`detailRowOpen(dimensionTrackFr + 1)`) that diverges regardless of mapped/unmapped input, confirmed `uat05-co-winner-...` itself goes RED with a diagnosable message, then reverted. `wr02`'s own established mutation-proof (from its originating plan) still covers the literal the plan named.
- **Files modified:** `MMM-SPCOutlook.js` (mutation applied and reverted verbatim; zero net diff).
- **Verification:** `git status --porcelain -- MMM-SPCOutlook.js` empty after revert; `node scripts/probe-payload-resilience.js` → `191 passed, 0 failed, 0 skipped`.
- **Committed in:** No commit (mutation cycle only; reverted before any commit was made). Documented here per Task 3's own requirement to record every cycle in the SUMMARY.

**2. [Rule 1 - Bug] `wr07-assert-inert-markup`'s grid-row fixture entry was disconnected from the code it claimed to test**

- **Found during:** Task 3, mutation cycle 6 (`wr07-assert-inert-markup-accepts-module-tags-and-rejects-everything-else`, the `<span>`→`<div>` mutation).
- **Issue:** Task 1's grid-row-opener fixture entry (added to this scenario's `legitimate` array) was a hand-typed literal string mirroring the shape `detailRowOpen` emits, not derived from actually calling the render path. Mutating `detailRowOpen` in `MMM-SPCOutlook.js` had zero effect on this hand-typed literal — the scenario stayed green under a real `<div>` mutation, which is the exact Phase 15 D-10 vacuity failure mode ("a fixture that never reaches the code it claims to test") this mutation-proof step exists to catch.
- **Fix:** Rewrote the fixture to render a real detail-row payload via `renderDom` and extract the grid-row-opener substring from the actual output, then feed that extracted string into `assertInertMarkup`. The `<div>` mutation now fails this scenario immediately (via `renderDom`'s own automatic `assertInertMarkup` call) with the required `"is not a tag MMM-SPCOutlook.js emits"` message.
- **Files modified:** `scripts/probe-payload-resilience.js`.
- **Verification:** Re-ran the `<span>`→`<div>` mutation after the fix; confirmed RED with the correct message; reverted; suite returns to `191 passed, 0 failed, 0 skipped`.
- **Committed in:** `a0d0ee8` (Task 3 commit).
