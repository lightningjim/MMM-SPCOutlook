## Copy + header ownership

### Q1 — How should the header work?

Context established before asking: `SPC FORECAST` is the operator's own `header:` line in
`config.js` and appears nowhere in the repository (`grep` across `*.js`/`*.md` confirmed, excluding
`.planning/`). The module defines no `getHeader()`, so it has no other lever on that string.

| Option | Description | Selected |
|--------|-------------|----------|
| Fallback default only | `getHeader()` returns `this.data.header \|\| <neutral default>`. A configured header survives verbatim; an unconfigured one gets accurate copy. Operator's own `SPC FORECAST` untouched; new users land on correct copy by default. | ✓ |
| Don't touch it — document only | No `getHeader()`. `header:` is operator-owned by MagicMirror convention; README + release notes carry a suggested value. Zero code risk, but existing users keep stale copy until they read the notes. | |
| Override unconditionally | Always return the module's own string, ignoring config. Guarantees accurate copy everywhere including the operator's Pi, but silently discards a deliberate setting with no customisation path short of editing source. | |

**User's choice:** Fallback default only → D-02

### Q2 — What umbrella name?

| Option | Description | Selected |
|--------|-------------|----------|
| NWS | `NWS Hazard Outlooks` / `Loading NWS outlooks...`. SPC, WPC and CPC are NCEP service centers under the National Weather Service; HeatRisk is an NWS product. Nothing rendered originates outside NWS. | ✓ |
| NOAA | The operator's own words from the UAT. Correct but one level too coarse — NOAA also covers NHC, OPC, NOS and the satellite/fisheries lines, none of which this module touches. More recognisable to a non-specialist. | |
| No agency name | `Hazard Outlooks`. Sidesteps the agency question and survives a future non-NWS source, but loses the provenance signal that distinguishes official guidance from a third-party interpretation. | |

**User's choice:** NWS → D-03
**Notes:** Chosen over the operator's own "NOAA" phrasing from the UAT on precision grounds. Governs
both the header fallback and the loading string so the two cannot disagree.

### Q3 — How wide does the sweep go?

| Option | Description | Selected |
|--------|-------------|----------|
| User-facing strings + README | Header fallback, loading string, README description. Leaves `Log.*("SPC Outlook: ...")` prefixes, `GET_SPC_DATA`/`SPC_DATA_RESULT`, `this.spcrisk` and the `MMM-SPCOutlook` directory name alone — renaming any is a breaking change to every install's `config.js` for zero user-visible gain. | ✓ |
| Strings + README + log prefixes | Adds ~40 `Log.*` call sites across both files. Semi-user-facing since the operator reads `mm-out.log`, but a mechanical sweep inflating the diff of a render-width phase and breaking grep-ability of existing log history. | |
| Strings only — no README | Narrowest. Leaves the repo's front door describing an SPC-only module two milestones after it stopped being one. | |

**User's choice:** User-facing strings + README → D-05
**Notes:** Log-prefix sweep and the three rename options carried to `<deferred>`.

### Q4 — Headerless users

Asked because MagicMirror paints the header region only when a string exists, so a fallback changes
behaviour for anyone deliberately running the module headerless.

| Option | Description | Selected |
|--------|-------------|----------|
| Honor `header: ""` as opt-out | Fallback fires only when `this.data.header` is `undefined`. An explicit empty string is a deliberate "no header". A distinction MagicMirror already makes in `this.data`, so no new machinery. | ✓ |
| Accept the new header row | Any absent-or-empty header gets the default. Simplest predicate, but a user who stripped the header has no way back short of patching the module. | |
| Add a `showHeader` flag | Matches the module's per-feature-toggle convention, but adds an eleventh config key to the very phase adding config-key validation, and duplicates a control MagicMirror already provides. | |

**User's choice:** Honor `header: ""` as opt-out → D-04
**Notes:** `showHeader` recorded in `<deferred>` as considered-and-rejected, with the reason, so it
is not re-proposed during planning.

Claude/the planner. CONTEXT.md records the binding constraints for each rather than an open question —
the researcher and planner must not re-ask the user.

|---|---|---|
| Width fix mechanism | The major defect. CSS `ch` widths vs table/grid vs dropping strict alignment vs capping width each rewrite a different part of the UI-SPEC's character-offset contract, which spec-locks 23 as exact. | Discretion — constraints enumerated in CONTEXT.md (root cause at `:644`, compact rows also displaced, `textAlign` anchor at `:1059`, five locked Phase 19/review decisions, no CSS file precedent, UI-SPEC amendment required). |
| Width regression guard | The harness is `vm`/`fs`-only with a regex DOM stub, so it cannot observe width; the existing `rpt03-*` scenarios assert column indices and pass green while the layout overflows. | Discretion — three candidate mechanisms named (structural proxy / one real-DOM scenario / `MANUAL ONLY` row), all subject to Phase 15 D-10 mutation proof. |
| Config key validation | Allowlist scope (module `defaults` plus MagicMirror's own per-module keys, or every config warns falsely) and loudness (warn-and-continue vs load-time throw). | Discretion — recommended shape recorded: one `Log.warn` at `start()` with a nearest-`defaults`-match hint, following `resolveUpdateInterval()`'s once-only-log idiom. The actual failure was `dayReportDetails` vs `dayReportDetail`, which a bare "unknown key" warning would not have resolved. |
