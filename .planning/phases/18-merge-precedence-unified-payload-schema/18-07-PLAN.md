`merge-grid-anchor-observed-reads-spc-valid-and-expire`
  SPC day-1 categorical fixture carries `VALID_ISO` 2026-09-05T13:00:00+00:00 and `EXPIRE_ISO`
  2026-09-06T12:00:00+00:00 on the winning feature. Precondition: assert the fixture actually
  produced a non-`"NONE"` `day1.risk`, so an anchor of `null` cannot be explained by the polygon
  never winning. Primary: `sources['spc-convective'].gridAnchor` is `"observed"`;
  `days["1"].windowStart` is the truncated 13:00Z instant; `days["1"].windowEnd` is the 12:00Z
  instant; `days["1"].date` is `"2026-09-05"` — the NOMINAL start's calendar date, unshifted by the
  truncation. Control: `days["2"].windowStart` is 2026-09-06T12:00:00Z, proving day 2 uses the
  nominal grid and not a second truncated read.

`merge-grid-anchor-estimated-on-spc-day1-hard-failure`
  SPC day-1 fetch hard-fails with nothing cached. Precondition: assert `day1.risk` is `"NONE"`, so
  the estimated anchor is attributable to the failure and not to a fixture that silently succeeded.
  Primary: `sources['spc-convective'].gridAnchor` is `"estimated"` and all fourteen `days` keys are
  still present with well-formed `windowStart`/`windowEnd` — a fetch failure degrades the anchor, it
  never collapses the grid. Control: the observed-branch scenario above already proves the same
  fixture family can produce `"observed"`, so this scenario's `"estimated"` is not the only value the
  field can take.

`merge-grid-anchor-malformed-valid-iso-degrades-to-estimated`
  SPC day-1 fixture carries `VALID_ISO` and `EXPIRE_ISO` set to a non-ISO string. Precondition:
  assert the polygon still won, so this exercises the parse guard and not a missing feature.
  Primary: no throw, `gridAnchor` is `"estimated"`, `days` is fully shaped, and `assertPayloadIntact`
  passes. This is T-18-02.

`merge-grid-hazards-00z-feature-forward-aligns-to-next-grid-day`
  The MERGE-01 near-boundary case. SPC grid day 1 anchored nominally at 2026-09-05T12:00:00Z (VALID
  truncated to 13:00Z, EXPIRE 2026-09-06T12:00:00Z). A `wpc-hazards` Precipitation-layer `Heavy Rain`
  feature with `start_date` = Date.UTC(2026,8,6) and `end_date` = Date.UTC(2026,8,7).
  Precondition: assert the label reached the legacy `hazardsOutlook` block at all, so a missing grid
  entry cannot be explained by the feature having been filtered out.
  Primary: `days["2"].hazards` contains a `wpc-hazards` `Heavy Rain` entry with
  `dimension: "heavy-precip"`, and `days["1"].hazards` contains none. This is D-10's forward-align
  rule: a 00Z-00Z source day for calendar date Sep 6 maps to the grid day that STARTS at 12Z Sep 6.
  Control: a second feature with `start_date` = Date.UTC(2026,8,5) lands on `days["1"]` and not on
  `days["2"]`, proving the gate distinguishes the two adjacent source days rather than placing
  everything on one.
  Add a comment on this scenario recording that plan 18-02 Task 1 measured this placement flipping to
  grid day 1 when the truncated `VALID_ISO` is used as the offset anchor instead of the nominal
  `EXPIRE_ISO` minus 24 hours — that flip is exactly what this scenario exists to catch.

`merge-grid-heatrisk-12z-sample-maps-to-its-own-grid-day`
  HeatRisk catalog items at `idp_validtime` Date.UTC(2026,8,5,12) category 3 and Date.UTC(2026,8,6,12)
  category 1, with the SPC anchor nominal at 2026-09-05T12:00:00Z. Precondition: assert the legacy
  `heatRisk` block resolved a non-null category, so an empty grid cannot be blamed on the fetch.
  Primary: `days["1"]` carries a `heatrisk` entry with `value: 3` and `days["2"]` one with `value: 1`.
  Control: `days["3"]` carries no `heatrisk` entry, proving the mapping is per-sample and not a
  broadcast across the window.

`merge-grid-heatrisk-yesterday-noon-tile-still-covers-grid-day-1`
  Same fixture, but `helper._nowMs` pinned to 2026-09-06T06:00:00Z — inside the 00Z-12Z window where
  the SPC grid day 1 started at 12Z yesterday while `_todayUtcMs` is today's midnight.
  Precondition: assert the legacy `heatRisk.day1` is NOT the yesterday-noon tile, proving the legacy
  span filter really did discard it and the scenario is testing the side-channel rather than a value
  that was available anyway.
  Primary: `days["1"].hazards` still carries the yesterday-noon `heatrisk` entry. This is the
  false-negative-on-a-heat-safety-product case plan 18-03 Task 3 exists to close.

`merge-grid-12z-products-map-straight-through`
  SPC day-1 categorical at `SLGT`, ERO day 1 at a Slight tier, WSSI day 1 at MINOR, all in one poll.
  Precondition: assert all three legacy blocks carry their non-NONE values, so an absent grid entry
  cannot be explained by a fetch that produced nothing.
  Primary: `days["1"].hazards` carries one entry per source, with dimensions `convective`,
  `flash-flood` and `winter` respectively, and none of the three appears on `days["2"]`.
  Control: the same fixture with the SPC day-2 categorical also set produces the SPC entry on
  `days["2"]` and not on `days["3"]`, proving day indexing tracks the source's own day number
  (D-11) rather than being pinned to day 1.
