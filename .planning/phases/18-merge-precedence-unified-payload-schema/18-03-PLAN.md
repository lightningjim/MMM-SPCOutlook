<objective>
Re-bucket the two sources whose native day convention does not align with the SPC 12Z grid —
`wpc-hazards` (a genuine 00Z-00Z interval) and `heatrisk` (a 12Z point sample) — onto
`days["1"]`..`days["14"]`, and turn their readings into annotated hazard entries.

Purpose: MERGE-01's whole content is here. D-09 reverses 16 D-03's calendar-date bucketing for the
unified block, but D-01 forbids changing the legacy `hazardsOutlook`/`heatRisk` blocks. The only way
to satisfy both is to have each runner hand the merge stage the same raw values it already built its
own block from, and re-bucket those against the SPC anchor in the merge stage.

Output: two additive side-channel keys on existing runner return objects, one grid-bucketing pass per
source, and populated `hazards` arrays on the grid days those two sources reach.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| WPC/CPC ArcGIS `start_date`/`end_date` -> grid day loop bounds | Upstream-controlled epoch values directly determine a loop's iteration count. |
| NWS HeatRisk `idp_validtime`/category -> registry map lookups | Upstream-controlled values become object property keys. |
| Upstream `label` strings -> `days[].hazards[].label` / `sources[].unmappedLabels[]` -> socket -> frontend | D-07 passes unmapped labels through verbatim to a renderer that Phase 14 IN-03 showed uses unescaped `innerHTML`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-03 | Denial of Service | `_addHazardsOutlookGridEntries` day loop | mitigate | Loop bounds clamped at the header with `Math.max(gridStart, 1)` / `Math.min(gridEnd - 1, GRID_DAY_COUNT)`, never filtered inside the body — the exact form T-16-05 closed in `_bucketHazardMatch` for a hostile `[-1e9, 1e9]` span. |
