<objective>
Move every non-day-scoped item into one band below the day blocks, and make the unified report the
sole render path.

**A second payload gap found at planning time, verified by source read.** The window-spanning
Hazards Outlook entries live **only** inside the legacy `hazardsOutlook.windowBand` block
(`node_helper.js:970`, assembled at `:936-970`). Phase 18's unified payload carries only a
*count* of them (`summary.bandDiagnostics.windowBandCount`, `:3548`), never the entries. RPT-04
requires those entries render in the band, and PROJECT.md requires the renderer read no legacy
block. Therefore the array must be promoted to a top-level payload key before the band can be
built without a legacy fallback. This is relocation of an already-assembled value into the
payload shape the new renderer reads — not new product, fetch, or merge logic.

**RPT-04 is a deliberate reordering, not a parity target.** Today advisories render *above* every
day row (`MMM-SPCOutlook.js:513-540`) and the window band renders *after* them at the very end
(`:682-730`). RPT-04 requires all three below the day blocks. RESEARCH Pitfall 3 predicts a parity
reviewer will file this as a regression unless it is recorded as verified-intentional — plan 19-01
created the `RPT-04-RELOC` row for exactly this, and this plan ticks it.

Purpose: RPT-04 (band below day blocks), RPT-01 (no per-product sections remain), RPT-06.
Output: one band, one render path, and a grep gate proving zero legacy-block reads.
</objective>
