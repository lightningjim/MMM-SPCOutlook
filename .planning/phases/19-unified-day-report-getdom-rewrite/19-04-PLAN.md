<objective>
Rewrite the head of `getDom()` and replace every per-product day section with one compact line
per day driven by the unified payload.

**Render-mechanism decision, made here and binding for the rest of the phase: keep
`wrapper.innerHTML += "..."` string concatenation. Do not switch to
`createElement`/`appendChild`.** Rationale, and the cost that decided it: the project's only
executable verification surface is `scripts/probe-payload-resilience.js`, whose DOM stub
(`scripts/probe-lib/module-stubs.js:263-298`, verified) is a flat
`{ innerHTML: "", textContent: "" }` object with no `appendChild`, no per-node `style` object and
no child-node tree. 15+ existing scenarios depend on that exact shape. Switching mechanism means
rewriting that stub into a minimal real element tree *before* any frontend scenario — existing or
new — can run against the new code, i.e. adding a parallel test-infrastructure rewrite to the
phase STATE.md already flags as the milestone's highest regression risk. WR-02's benefit
(text nodes cannot carry markup) is obtained more cheaply and more verifiably by applying the
three guards this codebase already owns at every call site, which is what this plan's acceptance
criteria enforce by grep. Consequent work of this decision: none beyond guard discipline — the
probe harness is untouched, and UI-SPEC.md's monospace requirement for detail sub-rows is
satisfied by one more inline `style` attribute (plan 19-05), so no CSS file is introduced and
`getStyles()` is unchanged.

Purpose: RPT-01 (one block per day, no per-product sections), RPT-02 (compact line), RPT-05
(correct empty state).
Output: a `getDom()` whose head and day loop read only `this.spcrisk.days`/`.summary`, with the
band still in its legacy position (relocated by plan 19-06).
</objective>
