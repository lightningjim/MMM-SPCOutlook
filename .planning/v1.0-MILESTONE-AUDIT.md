### Gap 2: QUAL-02 — Implicit Global `result` in evaluatePolygons()

**Blocker:** Partial — the code runs correctly in non-strict JS, but it is a genuine implicit global that violates QUAL-02.

**File:** `node_helper.js` line 104
**Code:** `result = turf.booleanPointInPolygon(loc, poly);` — no `const`/`let`/`var` keyword
**Impact:** Every polygon evaluation in every active flow (BUG-01, FIRE-02, CIG fetch-and-extract) goes through this function. In non-strict JS the `result` assignment silently pollutes the global object. In async contexts with overlapping evaluations there is a race condition risk.

**Why missed:** The Phase 5 grep verification checked `\bvar\b` — a bare assignment with no declaration keyword is not caught by this pattern.

**Resolution:** Add `let result;` declaration before the forEach block at approximately line 100 of `node_helper.js`.

Also in this class (dormant but present):
- `minDistTest` at line 165 in `evaluatePolygonsContinuous()` — same pattern, function never called
- `lambda` at line 139 in `evaluatePolygonsWeighted()` — undeclared reference, would crash if called
